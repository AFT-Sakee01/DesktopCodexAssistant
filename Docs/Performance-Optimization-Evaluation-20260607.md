# 性能优化评估报告

日期：2026-06-07  
对象：Codex Developer Assistant Window on WOA ARM64  
配置：BatterySaver、AlwaysVisible、悬停透明度启用、GFW 检测 30 分钟

## 结论

- 单核等效 CPU 从约 1.87% 降至 0.60%，降幅约 68%。
- 6 个可见模块在三轮挂起/恢复压力测试后全部恢复，进程持续响应。
- GDI 对象稳定为 75，USER 对象稳定为 67，没有持续增长。
- 恢复压力测试期间写操作增量为 0，写入字节增量为 0。
- 正常运行的程序逻辑写入量预计约 30-60 KB/天；频繁重启或手动 GFW 测试会增加该数值。
- 以 60 KB/天估算，年写入量约 21 MB，对 SSD 寿命没有可测量影响。

## 优化前基线

| 项目 | 基线 |
| --- | ---: |
| 单核等效 CPU | 1.87% |
| 工作集 | 101.7 MB |
| 私有内存 | 75.5 MB |
| 句柄 | 842 -> 837 |
| 线程 | 25 -> 24 |
| GDI | 65，稳定 |
| USER | 72，稳定 |
| 进程写入外推 | 约 490 KB/天 |
| 历史持久文件增长 | 约 301.57 KB/天 |

历史写入偏高的主要原因：

1. INFO 日志逐条写入。
2. 日志接近上限时反复重写尾部。
3. GFW 每 30 分钟写入完整探测明细。
4. 开发期间频繁启动产生多组初始化日志。

## 优化后实测

连续 80 秒稳定运行：

| 项目 | 结果 |
| --- | ---: |
| 单核等效 CPU | 0.60% |
| 全机 CPU（18 逻辑处理器） | 0.034% |
| 工作集范围 | 102.8-107.0 MB |
| 私有内存范围 | 76.6-77.0 MB |
| 句柄范围 | 848-856 |
| 线程范围 | 23-26 |
| GDI | 75，稳定 |
| USER | 65-67，稳定 |

GDI 基线增加 10 个是预期结果：5 个分层窗口各长期持有一个内存 DC 和一个 HBITMAP。对象数量稳定，替代了透明度动画期间反复创建和删除 GDI 对象。

## 恢复测试

测试过程：

1. 向 6 个可见窗口发送显示恢复和显示变化消息。
2. 连续执行 3 轮挂起消息与自动恢复消息。
3. 每轮后检查可见窗口、响应状态、句柄、线程、GDI、USER 和日志。

结果：

- 可见窗口始终为 6。
- 进程始终处于响应状态。
- GDI/USER 保持 75/67。
- 三轮压力测试期间硬盘写操作与写入字节均为 0。
- `error.log` 最后修改时间仍为 2026-06-06 20:50:39，本轮没有新增异常。

## 每日硬盘写入评估

正常运行时的主要持久写入：

| 来源 | 新策略 | 预计每天 |
| --- | --- | ---: |
| 主 INFO 日志 | 64 KB 或 5 分钟批量刷新；采样诊断每 15 分钟 | 20-40 KB |
| GFW 明细 | 状态变化/手动测试立即写；稳定状态最多每 6 小时一次 | 4-8 KB |
| 错误日志 | 仅异常时立即写 | 正常为 0 |
| 设置文件 | 仅用户保存设置时写 | 通常接近 0 |
| Codex 会话 | 只读，不由本程序写入 | 0 |

综合估计：约 30-60 KB/天。即使按 100 KB/天保守计算，年写入量也只有约 35.7 MB。

说明：上述数据是进程逻辑写入量。Windows 文件缓存、文件系统日志、SSD 写放大和系统其他进程不在本程序控制范围内，实际 NAND 写入量需要 ETW、厂商 SMART 或存储控制器统计才能测量。
